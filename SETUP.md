# Sydney itinerary — local Mac origin

Latest direction: all app serving, development, publication refresh and tests run on the existing Mac mini. Viewers need no Google account or passcode. Google Sheet remains private. GitHub is a private source backup, not the app host. The former Pages workflow has been removed; no cloud deployment runs on push.

Run `npm test`. Run `node scripts/serve-local.mjs` for the generic shell at http://127.0.0.1:4180. It binds only loopback, serves exact shell filenames, rejects writes, and returns 503 for `/api/published` until a reviewed release exists. It never serves the project root or the private directory. The existing real-data review remains localhost-only on port 4175.

The browser reads only the same-origin `/api/published` response. It contains `{rows, publishedAt}`; there is no Google SDK, Sheet identifier, credential or viewer login in the client. The local origin reads only `private/public-release.json` whose exact SHA-256 must match `private/public-release.approval.json`. No release or approval file is created automatically. This is an accidental-disclosure guard, not an authentication system: an externally exposed endpoint would be public.

Before release, review a deliberately redacted projection of Published. Do not copy the raw twenty-column snapshot wholesale. Review titles, trip dates/times, public venue locations, transport and tentative/confirmed status. Prices, payments, original currencies/rates, source IDs, free-form private notes, Sheet URLs, booking links/references, accommodation/residential addresses, names and personal plans require separate explicit inclusion decisions. Generic weather and publicly listed shop addresses/Apple Maps links are also listed in the release review. Public trip timing can reveal absence from home; public link approval must cover the concrete payload.

Keep the twenty-column private Sheet snapshot and its existing backup/publication workflow intact. The same end-of-day Sydney/on-demand operation can call `node scripts/build-snapshot.mjs private/source.json private/snapshot.json` to calculate once, then fetch a best-effort forecast and freeze it into Notes. This helper does not write the Sheet or install a scheduler. The active publisher still needs its existing operation updated to consume this helper; it has not been rewired by this change. App Refresh reads the resulting release; it never publishes working edits or fetches weather independently.

Optional Notes metadata uses `[itinerary-details:v1]` / `[/itinerary-details]` around JSON `{summary,stops:[{name,address,url,hint,children}]}`. Only HTTPS Apple Maps links render. Branches remain separate children. Weather uses `[itinerary-weather:v1]` / `[/itinerary-weather]` around `{timeZone:"Australia/Sydney",provider:"Open-Meteo",fetchedAt,days:{"YYYY-MM-DD":{location:"sydney"|"copacabana",high,low,code}}}`. No new Sheet columns. Metadata is hidden from ordinary prose. The current checkout uses saved publication forecasts only; out-of-range/unavailable/unclear return-day locations show a neutral dash.

After a successful online load, IndexedDB saves the last good snapshot, never credentials. A service worker caches allowlisted shell assets only, never the data API. Offline navigation, details, addresses and saved forecast work after that first load. Refresh failures retain the last good snapshot. Clear saved removes browser-local itinerary values. Browsers can evict storage; maps/new data require a connection. Real iPhone Safari/Home Screen verification remains required.

External HTTPS routing is not enabled. A proposed outbound HTTPS reverse tunnel could relay a hostname to this Mac’s loopback port 4180 without running app code in the cloud or opening router ports. The relay would still handle public requests and TLS. A provider/account/domain decision and specific exposure confirmation are required before installing/configuring a connector, creating routes, opening ports or changing network/security settings. No firewall/router/VPN/sleep/login setting was changed. Off-network and locked-screen behavior have not been tested.
