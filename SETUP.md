# Sydney itinerary — public sharing

Henry explicitly approved a public, account-free GitHub Pages site showing the full main itinerary on 19 November 2026. This supersedes the earlier Mac-only serving and redacted-payload proposals. The source repository is public; credentials, unrelated research tabs and local runtimes remain excluded. Development/build/tests run on the Mac. The Google Sheet stays private. GitHub Pages serves the static package from the gh-pages branch; no cloud test/deployment workflow is installed.

Run `npm test`. Run `node scripts/serve-local.mjs` for the generic shell at http://127.0.0.1:4180. It binds only loopback, serves exact shell filenames, rejects writes, and returns 503 for `/api/published` until a reviewed release exists. It never serves the project root or the private directory. The existing real-data review remains localhost-only on port 4175.

The browser reads only the same-origin `/api/published` response. It contains `{rows, publishedAt}`; there is no Google SDK, Sheet identifier, credential or viewer login in the client. The local origin reads only `private/public-release.json` whose exact SHA-256 must match `private/public-release.approval.json`. No release or approval file is created automatically. This is an accidental-disclosure guard, not an authentication system: an externally exposed endpoint would be public.

The current public release is the full verified main-itinerary snapshot, including notes and details, as explicitly requested. Check every future release for credentials or signed/private tokens before uploading. Scratch drafts and other research tabs are excluded. Anyone can read/copy public itinerary values and repository deployment history. The Google Sheet’s access permissions are unchanged.

Keep the twenty-column private Sheet snapshot and its existing backup/publication workflow intact. The same end-of-day Sydney/on-demand operation can call `node scripts/build-snapshot.mjs private/source.json private/snapshot.json` to calculate once, then fetch a best-effort forecast and freeze it into Notes. This helper does not write the Sheet or install a scheduler. The existing Dot automation updates the Sheet only and has no specified Mac execution; it cannot be assumed to invoke this local helper. No standalone Node Google authorization adapter is configured. A single-owner Mac migration must settle authorization, preserve Sydney-time DST handling, and verify the old job is paused before enabling any local timer. No migration or duplicate scheduler is installed. App Refresh reads the resulting release; it never publishes working edits or fetches weather independently.

Optional Notes metadata uses `[itinerary-details:v1]` / `[/itinerary-details]` around JSON `{summary,stops:[{name,address,url,hint,children}]}`. Only HTTPS Apple Maps links render. Branches remain separate children. Weather uses `[itinerary-weather:v1]` / `[/itinerary-weather]` around `{timeZone:"Australia/Sydney",provider:"Open-Meteo",fetchedAt,days:{"YYYY-MM-DD":{location:"sydney"|"copacabana",high,low,code}}}`. No new Sheet columns. Metadata is hidden from ordinary prose. The current checkout uses saved publication forecasts only; out-of-range/unavailable/unclear return-day locations show a neutral dash.

After a successful online load, IndexedDB saves the last good snapshot, never credentials. A service worker caches allowlisted shell assets only, never the data API. Offline navigation, details, addresses and saved forecast work after that first load. Refresh failures retain the last good snapshot. Clear saved removes browser-local itinerary values. Browsers can evict storage; maps/new data require a connection. Real iPhone Safari/Home Screen verification remains required.

The earlier Cloudflare relay proposal is superseded by GitHub Pages. No Mac inbound route, tunnel, firewall/router/VPN/sleep/login setting was changed. The public site can serve while the Mac is asleep/offline; future Sheet-to-site publication is still a separate, unresolved automation integration.


## Static Pages package

After an explicitly approved private Sheet publication and independent readback, save its rows and publication timestamp to ignored private/public-release.json with the matching reviewed SHA-256 approval. Run `node scripts/build-public-site.mjs`; this copies only web assets plus the approved published.json into private/public-site. It uses a relative snapshot URL for the GitHub Pages repository subpath and automatically loads the public snapshot without viewer login. Push that exact package to the gh-pages branch. Main remains source only; actual public itinerary data exists on the deliberately public deployment branch. Sheet Refresh cannot publish drafts. The current Dot nightly task updates private Published only; it does not automatically rebuild/push Pages. Do not claim continuous Sheet-to-site sync until migration is completed.
